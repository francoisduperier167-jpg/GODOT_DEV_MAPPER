validation humaine fréquente.

Lorsque contrats et tests sont stables :

l’IA peut exécuter des tâches plus autonomes.

Définir différents niveaux :

LEVEL 0 — analysis only

LEVEL 1 — design proposal

LEVEL 2 — single file implementation

LEVEL 3 — small multi-file change

LEVEL 4 — feature implementation under stable contracts.

Ne jamais donner automatiquement LEVEL 4 sur une zone expérimentale.

# 58. CRITÈRE FONDAMENTAL

La méthodologie doit empêcher trois problèmes majeurs :

### DÉRIVE ARCHITECTURALE

Le projet ne doit pas devenir un assemblage incohérent de fichiers générés indépendamment.

### HALLUCINATION API

Aucune API Godot ou API interne ne doit être inventée silencieusement.

### BIG BANG DEVELOPMENT

Ne jamais essayer de générer l’intégralité du système avant d’avoir validé plusieurs vertical slices.

---

# 59. NE PAS SUR-ENGINEER

La méthodologie doit être rigoureuse mais rester adaptée à un projet réel.

Ne crée pas 40 processus bureaucratiques inutiles.

Pour chaque mécanisme proposé, demande :

« Quel risque concret ce mécanisme évite-t-il ? »

Si la réponse n’est pas claire, simplifie.

cohérence ;

traçabilité ;

progressivité ;

réversibilité ;

maintenabilité ;

contrôle humain ;

Construis maintenant cette méthodologie complète.
